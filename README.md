## Архитектура

Сервис поддерживает два способа отправки уведомлений.

### 1. Через Kafka

1. `user-service` создаёт или удаляет пользователя.
2. `user-service` публикует событие в топик `user-events`.
3. `notification-service` получает событие через Kafka Consumer.
4. `EmailNotificationService` определяет содержание письма и отправляет его через SMTP.
5. Mailpit принимает письмо и позволяет просмотреть его в веб-интерфейсе.

Схема взаимодействия:

`user-service → Kafka → notification-service → Mailpit`

### 2. Через REST API

1. Клиент отправляет HTTP POST-запрос в `notification-service`.
2. Контроллер получает email и операцию пользователя.
3. `EmailNotificationService` формирует и отправляет письмо.
4. Клиент получает HTTP-ответ.

Схема взаимодействия:

`Клиент → REST API → EmailNotificationService → Mailpit`

Оба способа используют общую логику отправки писем.

## Обработка Kafka-событий

Топик: `user-events`

Событие содержит операцию и email пользователя.

Пример события при создании пользователя:

```json
{
  "operation": "CREATE",
  "email": "user@example.com"
}
```

Пример события при удалении пользователя:

```json
{
  "operation": "DELETE",
  "email": "user@example.com"
}
```

### Уведомления

При создании пользователя отправляется письмо:

**Тема:** Аккаунт успешно создан

**Текст:**

Здравствуйте! Ваш аккаунт на сайте ваш сайт был успешно создан.

При удалении пользователя отправляется письмо:

**Тема:** Аккаунт удалён

**Текст:**

Здравствуйте! Ваш аккаунт был удалён.

Операция `UPDATE` не отправляет письмо в соответствии с текущей реализацией сервиса.

## REST API

### Отправить уведомление

**Метод:** POST

**Endpoint:** `/api/notifications/email`

**Полный адрес при стандартных настройках:**

`http://localhost:8081/api/notifications/email`

Заголовок:

`Content-Type: application/json`

### Уведомление о создании пользователя

Тело запроса:

```json
{
  "email": "user@example.com",
  "operation": "CREATE"
}
```

### Уведомление об удалении пользователя

Тело запроса:

```json
{
  "email": "user@example.com",
  "operation": "DELETE"
}
```

При успешной отправке API возвращает статус HTTP 200 и сообщение:

`Уведомление отправлено`

### Пример проверки через curl

Отправка уведомления о создании:

```bash
curl -i -X POST http://localhost:8081/api/notifications/email \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","operation":"CREATE"}'
```

Отправка уведомления об удалении:

```bash
curl -i -X POST http://localhost:8081/api/notifications/email \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","operation":"DELETE"}'
```

## Настройки приложения

Основные настройки в `application.properties`:

| Параметр | Значение |
|---|---|
| Порт REST API | `8081` |
| Адрес Kafka | `localhost:9092` |
| Группа Kafka Consumer | `notification-service-group` |
| Топик Kafka | `user-events` |
| SMTP-сервер | `localhost` |
| SMTP-порт | `1025` |

Для локальной разработки используется Mailpit.

Веб-интерфейс Mailpit по умолчанию доступен по адресу:

`http://localhost:8025`

Mailpit позволяет просматривать перехваченные письма без отправки реальной почты пользователям.

## Запуск приложения

### Предварительные требования

Перед запуском убедитесь, что установлены:

- Java 17 или более новая совместимая версия;
- Kafka;
- Mailpit.

Kafka и Mailpit должны быть запущены отдельно от приложения.

### Запуск notification-service

Выполните команды в корневой папке проекта.

Сборка и запуск тестов:

```bash
./mvnw test
```

Запуск приложения:

```bash
./mvnw spring-boot:run
```

Также приложение можно запустить из IntelliJ IDEA через класс `NotificationServiceApplication`.

## Тестирование

Интеграционные тесты проверяют отправку писем двумя способами:

1. Через REST API.
2. Через Kafka.

Проверяются уведомления о создании и удалении пользователя, адрес получателя и содержание письма.

Для тестирования используются тестовый Kafka-брокер и GreenMail, позволяющий проверять получение писем без настоящего почтового сервера.

Для запуска тестов выполните:

```bash
./mvnw test
```

Тесты должны завершиться успешно до публикации изменений в репозитории.
